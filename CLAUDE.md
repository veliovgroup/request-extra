# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`request-libcurl` (repo name `request-extra`): a single-file callback and Promise wrapper around the `node-libcurl` native addon. Published to npm as `request-libcurl`. Node.js >= 22.15 only; Bun is blocked upstream (see `docs/platform-notes.md`).

## Commands

```shell
npm test                 # test:local + test:types (the required gate)
npm run test:local       # mocha, deterministic; SKIP_EXTERNAL=true skips httpbin/badssl cases
npm run test:external    # same suite with httpbin.org / badssl.com cases enabled; needs network
npm run test:types       # tsc over test/tsconfig.{node,node-cjs,bun}.json
npm run test:package     # pack tarball, install into test/package-consumer, run runtime + type checks, then attw
npm run test:bun         # compatibility probe only; expected to fail until Bun fixes libuv gaps
npm run test:coverage    # c8 over test:local; writes coverage/lcov.info
npm run lint             # eslint
npm run lint:package     # publint
npm run build            # rollup index.js -> index.cjs
```

Run a single test: `npx cross-env SKIP_EXTERNAL=true mocha ./test/npm.js ./test/local.js -g "pattern"`.

## Source layout and build

- `index.js` is the only source file (ESM). `index.cjs` is generated by rollup and is committed. After editing `index.js`, run `npm run build` and commit both files; CI does not regenerate it for you.
- `index.d.ts` and `index.d.cts` are hand-written and must stay identical except for module format. Package `exports` maps `import` to `index.js`/`index.d.ts` and `require` to `index.cjs`/`index.d.cts`.
- Published tarball is exactly `index.js`, `index.cjs`, `index.d.ts`, `index.d.cts`, `package.json`, `README.md`, `LICENSE`. `test/packed-package.mjs` asserts this list; update it when `files` changes.

## Architecture of index.js

Request lifecycle is split across three layers:

1. `normalizeOptions()` merges `request.defaultOptions` with caller options and throws `TypeError` synchronously on invalid input (types, negative numbers, non-integer counts, header names/values, HTTP method tokens). `validateCurlConfiguration()` preflights `curlOptions`/`curlFeatures` against `Curl.option`/`Curl.feature` so bad native options fail before any transfer.
2. `sendRequest()` performs one attempt: builds the `Curl` handle, wires `onData`/`onHeader`/`pipeTo` writables with backpressure (`curl.pause(CurlPause.Recv)` when `write()` returns false, resumed on `drain`), and maps libcurl error codes to HTTP-like `statusCode` values (SSL codes -> 526, transport failures -> 503, aborted -> 499, bad URL -> 400, serialization -> 43/400).
3. `LibCurlRequest` owns the attempt loop: per-attempt timeout timer, `_retry()` with exponential backoff capped by `retryMaxDelay`, optional jitter, and `Retry-After` handling, plus `abort()`/`abortAsync()` which must clear both the retry timer and the per-attempt timeout.

Retry rules that tests enforce: retries never happen when `pipeTo`/`.pipe()`, `onData`, `onHeader`, or `upload` (file descriptor) are in use, because partial output or a consumed descriptor cannot be replayed. `retries` means additional attempts. Default `retryMethods` excludes POST and PATCH. Reusable error objects (`badUrlError`, `abortError`, `badRequestError`) are always spread-copied before being handed to callers so mutations do not leak between requests.

TLS verification (`rejectUnauthorized`, `rejectUnauthorizedProxy`) defaults to `false` on purpose for backward compatibility. Do not flip it without a major version bump.

## Tests

- `test/local.js`: deterministic tests against `test/helpers/local-server.js` (local `http.Server`). New behavior goes here.
- `test/npm.js`: legacy suite; external cases are wrapped in `externalIt` and skipped under `SKIP_EXTERNAL=true`.
- `test/fixtures/*.js`: child-process scripts spawned by tests that need a separate process (fd 0 uploads, abort timers, stream error handling). Tests assert on exit code and stdout.
- `test/types-*.ts` and `test/package-consumer/`: type-level tests compiled with `tsc --noEmit`; the consumer copy runs against the packed tarball rather than a self-reference.

## CI

`.github/workflows/ci.yml` runs on PRs and pushes to `master`: Ubuntu matrix (Node 22.15.0, 24, 26) runs lint, test, build, audit, publint, packed-package checks, and pack dry-run; macOS, Windows, and a `node:24-alpine` container run `test:local` as native-install smokes (Alpine covers the musl prebuilt); a `continue-on-error` Bun probe runs `test:bun`. `external.yml` runs `test:external` weekly and on manual dispatch. Actions are pinned by SHA. Details in `docs/ci-plan.md`.

`npm audit` findings usually come from `node-libcurl` install-time dependencies (`node-gyp`, `rimraf`), not runtime code. Root `overrides` in `package.json` pin patched versions for this repo only; they do not propagate to consumers.

## Conventions

- Commit headers start with one emoji, then `type: scope / title` (`🔧 fix: retry / skip retries for descriptor uploads`, `📦 v 5.0.1`).
- Releases are manual: bump version in `package.json`, update `CHANGELOG.md`, tag, `npm publish` from a local checkout. `prepack` runs the build.
- `docs/superpowers/` is gitignored working notes; do not reference it from tracked files.
- Dependency updates to `node-libcurl` need the full Node matrix green because prebuilt binary availability differs per ABI, OS, and libc.
